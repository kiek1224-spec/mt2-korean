# c07 상점 수정

c06의 악마 번역을 유지하고 사용자가 제공한 c04 `_3.mss` 상점을 수정했다. 일본어 원본 및 Darrman의 아이템·선택지·script 2 덤프를 대조했다. 전체 상점이나 전체 게임의 번역 완료판은 아니다.

## 번역

| 아이템 ID | 원문 | c07 |
|---|---|---|
| 11 | ジャックナイフ | 잭나이프 |
| 12 | せいどうのつるぎ | 청동검 |
| 15 | シミター | 시미터 |
| 19 | ブロードソード | 브로드소드 |
| 31 | バトルスーツ | 전투복 |
| 32 | ハイレグアーマー | 하이레그 아머 |
| 34 | ケブラーベスト | 케블라조끼 |
| 46 | アイアンヘッド | 철투구 |

ID는 16진수다. 목록은 별도 선택지 ID 21~25, 59~5B를 사용한다. 실제 아이템 이름만 바꾸면 목록은 바뀌지 않는다. 두 테이블에 같은 이름을 반영했고 가격은 보존했다. 깨진 여성 기호와 남성 기호는 남/여로 표시한다.

- 자수아 → 소지금.
- 구매 `[아이템]이신가요?` → `[아이템]인가요?` (원문 `[VarItem]ですね?`).
- 판매 `[아이템]네 ₭[금액] 정도인데요.` → `[아이템] / ₭[금액]에 사겠습니다.` 원문의 말끝 ね를 한국어 네로 옮긴 오류를 제거했다.
- 판매 후 질문 → `더 파실 물건이 있나요?`.
- 공통 확인창의 일본어 원시 타일 → `네 / 아니요`.
- `무엇을 찾으시나요?`는 원문 `なにを おさがしですか?`에 맞으므로 유지했다.

## 구현과 용량

아이템 포인터 219개를 다시 배치했고 선택한 8개 외 문자열은 바이트 단위로 보존했다. 이름 영역은 0x439C6..0x43F81, 1467/1467바이트다. 선택지 92개도 보존 검사를 거쳐 재배치했다. 영역 0x6BCEC..0x6C010 중 679/804바이트를 사용한다. 이름 출력 폭·성별 칸·가격 칸은 유지했다. 철의 비트맵을 gid 762에 넣었으며 남은 글꼴 라이브러리 빈 슬롯은 5개다.

소지금 제목은 정적 타일맵 0x577E3에서 온다. 기존 한글이나 그래픽을 덮어쓰지 않도록 동적 슬롯 B7을 금(gid 112) 전용으로 예약했다. 일반 글자는 98..B6의 31칸을 순환한다. 할당기와 업로더가 금에서 카운터를 올리지 않도록 함께 수정했다. 제목을 그릴 때 금을 큐에 넣으므로 예전 세이브를 불러와도 새로 그리면 갱신된다. 빈 큐 NMI 분기와 부팅 코드는 그대로다.

카운터·글꼴 변경이 있으므로 c07 이후 코드는 c06의 32칸 가정을 사용하면 안 된다. 긴 다중 목록의 글꼴 수명 전체를 해결한 변경은 아니며 새로운 목록은 별도 확인한다.

## 확인한 결과

- 실제 상점 재입장 후 8개 목록 이름과 소지금 확인. 화면의 타일 비트맵을 한글 원본과 전부 대조했다.
- 잭나이프 구매로 184→84, 취소 시 184 유지. 사용자 원본 세이브는 변경하지 않았다.
- 구매 확인, 취소 후 목록, 판매 견적, 여러 거래 화면 이동을 확인했다. 반복 입력은 판매 화면으로도 이어졌으며 이를 단순히 같은 취소 동작 3회로 집계하지 않는다.
- 반복 화면 검사에서 금 비트맵이 틀린 프레임 0, 업로더가 화면 표시 중 CHR을 쓴 건수 0. 가장 늦은 기록은 scanline 255였다.
- 기존 악마 252개·종족 26개와 아이템 8개의 실제 CPU 이름 처리 검사가 모두 통과했다. 큐 포화 0건.
- 초기 부팅과 픽시 전투 표시, 일본어 원본용/c06용 IPS 왕복 통과.
- c06 대비 변경 2879바이트. 검증기가 허용 영역 밖 변경을 거부하고 미선택 문자열 보존을 확인한다.

증거는 `결과/codex/c07_verification.json`, `c07_build.json` 및 `결과/codex/verification/c07_*`에 있다. 모든 진단 롬은 후보에서 테스트용 변경만 재구성하여 실행 기록의 SHA256과 대조했다. 배포본에는 진단 이벤트가 없다. 최종 악마 전체 진단 해시가 판매 문구 수정 전후 같아도 정상이다. 진단 스크립트가 그 문구 영역까지 덮으므로 현재 후보로 재구성했을 때 동일한 바이트가 된다.

## 실행 및 재현

```
python tools/build_c07_shop.py
python tools/verify_c07.py --release
```

실행 롬: `작업한 롬파일/mt2_codex_c07_shop.nes`.
SHA256: `f4c01d285ed0cabf1a83cb1b0ec3565718975ab960eab7ea20ccfb8d3f547d54`.
패치: `패치파일/mt2_codex_c07_shop.ips`는 일본어 원본용, `mt2_codex_c07_FROM_c06.ips`는 c06 전용이다.

`_3.mss`의 캐시된 제목·목록은 그대로 보일 수 있다. 상점에서 나와 아래로 한 칸 이동한 뒤 위로 돌아와 재입장한다. 정확한 입력은 `c07_shop_final/run.json`에 보존했다. 판매 테스트 `c07_sale`은 원본 세이브에서 바로 시작했기 때문에 제목이 캐시된 자수아로 남지만, 새 판매 문장은 다시 읽어 표시됐다. 새로 입장한 제목의 검증 근거는 `c07_shop_final`이다.

남은 작업은 다른 상점·아이템, 필드와 전투의 별도 소지금 제목, 교섭 대화, 다른 UI다. 이미 완료한 첫 상점 검사와 분석은 다음 회차에 반복하지 않는다.
