# c08 그래픽·글꼴 충돌과 사람 상태창 수정

2026-09-25. c07에서 제공된 전투·상태창 깨짐을 재현하고, 별도 c08 검증판을 만들었다. 전체 한글화 완성판이나 전체 플레이 검증 결과는 아니다.

## 실행 파일과 재현

- 롬: `작업한 롬파일/mt2_codex_c08_status.nes`
- 일본어 원본용: `패치파일/mt2_codex_c08_status.ips`
- c07용 갱신: `패치파일/mt2_codex_c08_FROM_c07.ips`
- 최종 해시와 근거: `결과/codex/c08_build.json`, `결과/codex/c08_verification.json`
- 빌드: `python tools/build_c08_renderer.py` (py65 필요)
- 실행 검사: `python tools/probe_c08.py status` 등. `status`, `battle`, `shop`, `coldboot`, `corrupt_save` 지원.
- 이름 검사: `python tools/probe_c06_names.py demons --rom 결과/codex/experiments/mt2_experiment_c08_renderer.nes --tag c08 --renderer c08` (`races`, `items`도 각각 실행).
- 보존된 검사 결과와 일치해야 배포: `python tools/verify_c08.py --release`.

기존 c07 롬과 사용자 세이브를 덮어쓰지 않았다. 세이브 `_1`은 상태창을 새로 열어 검사했고, `_6`은 실제 전투에서 AUTO 선택 후 진행했다. `_4`는 이미 깨진 화면이 포함된 세이브로, 입력을 진행해 진료소 장면이 다시 그려지는 것까지 확인했다. 검사별 입력·롬 해시·원본 세이브 해시·화면·CHR 덤프는 `결과/codex/verification/c08_final_*/`에 있다.

## 확인한 원인

1. **NMI 처리 시간 초과.** 기존 한글 업로더가 두 글자를 올리느라 뒤에 실행되는 원작의 화면 쓰기를 늦췄다. 한글 업로드 자체가 수직 귀선 기간에 끝나도 원작 `$FA51 STA $2007` 쓰기가 프리렌더 구간까지 밀렸다. 상태창에서 글꼴 영역 밖 CHR `$11F3` 등이 변했고, 은행 그림자만 수정한 대조군에서는 빈 타일 `$1003`이 변해 점무늬 배경이 나타났다. c07의 “한글 업로드 중 표시 구간 쓰기 0건”은 원작 쓰기까지 검증한 결과가 아니었다.
2. **매퍼 은행 복원 누락.** 원작 `$F07D`, `$F092`의 `STX $8000`는 상태창 등의 CHR 데이터 은행을 바꾸지만 기존 업로더의 은행 기록은 갱신하지 않았다. 업로더가 다른 은행으로 복원할 수 있었다.
3. **게임 스택과 작업 공간 중복.** 기존 큐·변수 `$013D..$0164`는 원작의 여러 작업이 사용하는 스택 페이지 안이었다. 원작은 `$1F,$3F,$5F,$7F,$9F,$BF,$DF`를 스택 기준으로 사용한다. `_4`에서는 준비 표시 `$0164`가 `$A5` 대신 `$04`로 변해 업로드가 실행되지 않는 상태도 확인했다.
4. **매번 새 글꼴을 할당하고 문자를 누락하는 처리.** 장비 없음 문구가 여덟 번 반복돼도 매번 슬롯을 소비했고, 큐가 가득 차면 공백을 반환했다. 첫 캐시 후보에도 오래된 슬롯을 방금 재사용한 직후 FIFO 교체하는 결함이 있었다. 252개 이름 검사에서 `키쿠리히메` 첫 글자가 `히`로 바뀌는 사례를 잡아 최근 사용 순서에 따른 교체로 수정했다.

## 수정 내용

- 일반 화면 표시 중에는 NMI 한 번에 글꼴 한 개만 전송한다. 16바이트 전송 루프를 펼쳐 비용을 줄였다. 큐가 비면 원작 DMA 경로로 간다.
- 누락된 두 `STX $8000` 경로도 은행 값을 기록한다. 원작의 다른 네 `STA $8000` 후크는 유지했다.
- 글꼴 작업 공간은 `$7F80..$7FEB`, 최근 사용 정보는 `$7F60..$7F7E`로 옮겼다. 사운드 코드 정적 점검 및 c07 상태창·전투 실행에서 `$7F60..$7FFF` 읽기/쓰기는 0/0이었다. 모든 게임 분기에서의 미사용을 형식적으로 증명한 것은 아니다.
- 31개 일반 슬롯 `$98..$B6`의 최근 사용 정보와 문자 번호를 저장한다. 재사용할 수 있는 글자는 다시 전송하지 않는다. `$B7`은 금 전용이다. 큐의 상위 바이트에 대상 슬롯과 문자 페이지를 함께 기록해, 할당 순서와 업로드 순서가 달라져도 지정 슬롯에 쓴다.
- 표시 중 큐가 가득 차면 NMI가 비울 때까지 기다려 글자 누락을 막는다. 전체 화면을 그리며 NMI를 끈 상태창 경로에서는 먼저 큐를 직접 비우고 글자를 할당한다.
- 고정 은행의 호출 중계 코드가 원작의 프로그램 은행 기록 `$0343`도 갱신한다. 처리 중 NMI가 들어와도 실행 중인 코드 은행을 복원한다.
- 콜드 부팅에서는 새 캐시 표시와 업로드 준비 표시를 초기화한다. 기존 부팅 압축 해제 방식과 매퍼 19는 유지했다.

## 상태창 번역

Darrman의 `Cartographer/trimmed/status screen.txt`와 원작 화면 구조를 대조했다. 사람 상태창의 소지금·보석·상태·장비·체력·지력·공격·민첩·운을 바꿨고, EXP/NEXT 뒤에서 깨져 보이던 일본어 접미사는 비웠다. 숫자와 능력치 막대, 장비 그림은 유지한다.

상태창 배경은 일반 대사 문자열이 아니라 CHR에 들어 있는 압축 타일맵이다. 원작이 이를 풀고 아직 화면을 끈 시점에 해당 라벨만 그린다. `$FA:$063E`로 끝나는 사람 상태창 블록만 대상으로 한다. 장비 제목은 뒤에서 별도 복사되므로 그 경로도 두 한글 글자를 할당하도록 수정했다. 악마 상태창의 별도 레이아웃은 아직 번역하지 않았다.

## 검증 범위와 남은 일

- 악마 이름 252개, 종족 26개, 상점 아이템 8개: 실제 CPU 복사 및 큐 소진 뒤 실제 CHR 비트맵 대조. 총 286개 불일치 0건.
- 사람 상태창의 라벨·장비 없음 여덟 줄과 상점 글자: 163개 글자 비트맵 대조.
- 상태창 13회, 전투 9회, 상점 13회, `_4`에서 새 장면으로 이동하는 과정 5회의 스냅샷: 지정 글꼴 영역 외 CHR 변경 0바이트.
- 콜드 부팅과 한글 도입부 진행, 원본 세이브 보존, 두 IPS 적용 결과 일치.
- 매퍼 변경 근거가 없어 중국 매퍼 개발 조사는 이번 수정에 필요하지 않았다.

동시에 보이는 서로 다른 확장 한글이 31개를 넘는 문제까지 해결한 것은 아니다. 모든 장비 조합과 전체 플레이를 검증하지 않았다. 악마 상태창, 필드·전투의 별도 소지금 제목, 나머지 상점/아이템/긴 대사가 다음 대상이다. 부팅 속도는 바꾸지 않았다.

강제 세이브는 화면·글꼴·옛 큐 상태를 함께 보관한다. c07 세이브를 c08에 불러온 직후의 캐시된 화면을 새 렌더링 결과로 판단하지 않는다. 상태창은 닫고 다시 열고, 상점은 나갔다 다시 들어간다. `_4`의 저장 시점 화면을 임의로 고쳐 성공 화면으로 제시하지 않았다. 새 장면으로 진행하면 c08 경로로 다시 그려진다.
