# c11 전투 상태와 아이템 (2026-09-26)

배포 ROM: `작업한 롬파일/mt2_codex_c11_battle_items.nes`.
SHA256: `657d00d2315f3142e51d5c3ce95de62583bc64c6adb312ddfd46b879dba7c32c`.
일본어 원본용 `패치파일/mt2_codex_c11_battle_items.ips`, c10 갱신용 `mt2_codex_c11_FROM_c10.ips`.

## 완료와 검증

- c10 저장 소실 수정 유지. 최종 c11로 두 저장 슬롯을 각각 새 Mesen 프로세스에서 LOAD했다. 슬롯 4096바이트, 이름/파티, FF 표식이 유지되고 부팅 중 슬롯 쓰기는 0건이다.
- 전투/필드 하단 NAME/HIT-PTS/STATUS를 이름/체력/상태로 변경했다. MP는 기존 약어다.
- 상태 이상 17행(공백/중복 포함), 행동 13행을 번역했다. 공격, 소환, 귀환, 방어, 정렬과 사망/석화/마비/동결/수면/속박/혼란/행복/침묵/중독/정상/저주/돼지/팔 상실이다. 일반 대기 상태의 점 여섯 개는 유지한다.
- 아이템 219개 중 101개 번역: 기존 8개, 발터 PPK 두 ID, 소비품/중요 아이템 ID128..218의 91개. ID 중복은 원본 그대로다. 항목별 원문 대조는 남은 118개 목록에 보존했다.
- 실제 공용 이름 출력 루틴에서 101개 모두 복사/업로드 비트맵 검사를 통과했다. CPU 상태 처리 282칸, 화면 104글자/6656픽셀, 필드·전투·침묵 상태창·악마 상태창·상점의 비글꼴 CHR 변경 0바이트를 확인했다. IPS 두 종류 재적용 결과도 배포 ROM과 같다.

## 구현

`tools/build_c11.py`는 정확한 c10 SHA를 요구한다. bank30 D000의 159바이트 디스패처가 기존 F6D8 보존 브리지의 반환 주소로 상태 복사 경로를 구분한다. 표는 파일4643E/464AA의 6칸 형식을 유지하고 임시 토큰을 글리프 ID로 변환한다. 기존 장비 제목 디코더는 CB03으로 3바이트 이동했다. CBDB의 간접 읽기+저장 5바이트는 helper에서 동일 저장 후 복귀한다. C5B9의 파티 프레임 복사 경로에서 제목을 변환하며 제목 확장 글리프는 핀한다.

새 글자 묵은 실제 c10에서 FF인 gid763에 추가했다. c10 부팅 이행 서명 gid764..766은 건드리지 않는다. 남은 FF 글자 슬롯은 gid767 하나다.

아이템 포인터219개와 문자열을 bank30 CPU9200/93B6(파일3D210/3D3C6)으로 옮겼다. 공용 이름 descriptor 파일4E0EA는 `0A 1E 00 92`다. 이름 자체가 고르는 은행과 원본 접미사 사전 bank46은 독립적이므로 남은 일본어 문자열/사전 코드는 그대로 보존했다. 앞으로 포인터43810을 최신 아이템 표라고 가정하지 말 것.

## c09 강제 세이브 호환

c10에서 SRAM 캐시 주소가 바뀌었다. c09 강제 세이브를 곧바로 불러오면 새 RDY6000+47은 0이고 원래 플래그7FA7에만 A5가 있어 글자 큐가 멈추는 경우를 실제로 확인했다. c11 allocator 초기화는 bank31 DD00 호환 헬퍼를 통해 이전7FA7/7FA6에서 업로드 준비 상태와 PPU 은행 shadow를 복구한다. 원래0164/0163 경로도 유지한다. 이전 SRAM에는 쓰지 않는다.

강제 세이브 안의 이미 그려진 제목/문장/이름은 화면을 닫고 재진입해야 갱신된다. c09_2 보물상자 세이브는 이미 획득 문장을 그린 뒤의 상태라 첫 캡처는 옛 글자다. 그 캐시 화면을 새 번역의 검증 증거로 세지 않았다. 발터 PPK를 포함한 새 이름은 공용 출력 루틴으로 검증했다. 예전 세이브를 c11에 불러온 뒤 게임 안에서 다시 저장하여 진행한다.
