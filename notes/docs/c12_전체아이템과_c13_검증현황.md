# 갱신: 아래 c13 미해결 기록은 해결됨

F9의 원인은 캐시가 아니라 별도 일본어 `あくま` 리터럴이었다. 수정과 최종 실전 픽셀 검사 후 c13 배포 완료. 최신 결과는 [c13 기록](c13_전투문구_수정.md)을 따른다. 아래는 추적 당시 기록이다.

# c12 배포 / c13 검증 중

최신 배포: `작업한 롬파일/mt2_codex_c12_all_items.nes`.
SHA256 `6cc8906b418de5eb78270325436cd9ebd6e8fa57023aee55e0667aeaad97dfd7`.
패치 `패치파일/mt2_codex_c12_all_items.ips`(일본어 원본), `mt2_codex_c12_FROM_c11.ips`.

c11 저장 소실·전투 상태/행동·옛 강제 세이브 준비 플래그 호환 수정 포함. c12는 공용 아이템219개 전부 번역했다. 실게임 공용 이름 복사와 업로드219개, 두 슬롯 완전 재실행 LOAD, 상점 비글꼴 CHR 오염0, 두 IPS 재적용을 검증했다. 코드/맵퍼는 c11과 같다. 글자 킷은 gid767, 나머지 변경은 bank30 아이템 표 데이터뿐이다. `tools/verify_c12.py --release`가 배포한다.

## c13은 아직 배포하지 않음

전투 문구207개 번역안 `translations/combat_c13_ko.json`. 시험 ROM `결과/codex/experiments/mt2_experiment_c13.nes`, 현재 SHA `6c6c7dc097effd145347d5142cb2247015924df373f69dbf64ffe70d189e7199`.

전투 표290개를 다시 패킹했다. 기존 표는 1번 공백 문자열 속에2번 포인터가 들어가는 접미사 공유가 있으므로 다음 포인터를 종결로 간주하면 안 된다. 기존 B8/B9/C3 페이로드를 건너뛰어 FF종결까지 읽고, 번역하지 않은 메시지는 그대로 보존한다. 현재6023/6648바이트. 오프닝281..284 등은 유지한다. 자동이동256..280과 엔딩285..289, 일반·교섭 대사는 아직 별도 작업이다.

새 글자10개 껏/꿀/낮/떡/쉬/쏘/틸/획/휩/흡은 gid768..777(C4 00..09). bank31 D900에는 부팅 코드가 있어 절대 덮지 않는다. 실제빈 DB40..DBFF(파일3FB50,24글자capacity)를 쓴다. NMI uploader DC70의 STA AB/LDY0을 DD20 helper로 연결하여 page3 원본계산D900을 DB40으로+0240보정한다. DD00은 c11이전세이브호환helper이므로유지. F7E6고정helper는 일반대사F700의C3/C4를분기, F7D6의16바이트는 별도 이름읽기F67E의C3/C4를분기한다. 다른원본제어문자는기존경로유지. 이미그려진화면의동시31종한도는그대로다.

완료한 c13검사:207개대사 실제화면/한글픽셀(변수는 가/1 고정, pause 생략); 악마252/아이템219 복사와비트맵; 새글자10종+기존글자혼합; 두슬롯새프로세스LOAD; 오프닝. 증거 `c13_messages_runtime.json`, `c13_demons_runtime.json`, `c13_items_runtime.json`, `c13_glyphs_runtime.json`, `c13_save_verification.json`.

### 남은 검증 문제

`결과/codex/verification/c13_battle_cycle/screen11.png`에서 F9를사용하는처치문구의악마이름이 안메린 같은글자로보인다. 같은전투 VAR(=F4)의 그린 슬라임과 보상문구는정상이다. c09강제세이브에서복원한기존이름버퍼/동적캐시문제로의심하지만확정아님. 실전이름표시확인없이 c13을배포하지말것. `c13_battle_cycle/final.mss`는c13에서전투후필드로돌아온검사용상태다. 이를출발점으로새인카운터를만드는 `c13_fresh_encounter` 입력검사중. 사용자세이브는수정하지않았다.

`tools/probe_c13_messages.py`는diagnostic shop script로207개문구를순서대로그린다. 고정된변수이름과숫자를쓰므로 모든전투효과/실제긴이름의검증은아니다. 좌표는x5,y15,행간2. `--verify-only`로이미캡처된결과를다시검사할수있다.
