# c13 전투 문구 배포 완료

최신 ROM `작업한 롬파일/mt2_codex_c13_combat.nes`.
SHA256 `a5d372952f0e6596d74a3ea8a49fab9004d3b078d34ff558de76d6a122e9471e`.
원본용 `패치파일/mt2_codex_c13_combat.ips`, c12 갱신용 `패치파일/mt2_codex_c13_FROM_c12.ips`.

## 반영 범위

c10 저장 소실 수정, c11 전투 상태·행동과 이름/체력/상태 제목 및 옛 강제 세이브 호환, c12 공용 아이템219개 번역을 포함한다. c13은 공격·피해·특수 공격·상태 이상·회복·승리 보상 등207개 문구를 일본어 원문과 대조하여 번역했다. 누적 변경207개는 전부 신규 미번역이었다는 뜻이 아니며, 기존 어색한 문장도 교정했다.

## 실제 발견하고 고친 F9 미번역

F9는 특정 적의 이름이 아니다. 공용 이름 descriptor type4(파일4E0FA)가 bank53 BBB3의 포인터를 통해 BBB5의 일본어 `あくま`를 읽는다. 파일6BBC5의 `80 87 9E FF`가 안/메/동적타일로 표시된 것이 원인이었다. `8D 59 FF FF`(악마)로 수정했다. 캐시 문제라는 초기 가설은 폐기했다. 실제 c09_3 세이브에서 전투를 진행하여 `악마 1마리 / 쓰러뜨렸다`가 정상으로 표시되는 것을 확인했다.

## 검증

- 아이템219개, 악마252개: 실 CPU 공용 복사 및 업로드 비트맵 일치.
- 전투 문구207개: 실제 텍스트 엔진 캡처, 한글/공백2290칸 픽셀 일치. 이 검사는 변수 이름/숫자를 가/1로 고정하고 pause를 생략하므로 모든 전투 효과와 모든 이름 조합을 검증한 것은 아니다.
- 새 글자10종 껏/꿀/낮/떡/쉬/쏘/틸/획/휩/흡과 기존 C3 글자를 섞은 출력 성공.
- 최종 ROM에서33개 체크포인트의 전투·승리·필드·COMP 조작. F9 악마, 쓰러뜨렸다, 승리 보상, 복귀 후 제목 등30글자 실제픽셀 일치. 허용 글꼴 범위 외 CHR 변화0.
- 두 저장 슬롯을 각각 새 Mesen 프로세스에서 LOAD하여 저장 데이터4096바이트 유지, 표식FF, 이름/파티 일치. 오프닝도 실행했다.
- 저장·오프닝·대사 카탈로그·이름 전수 검사는 최종 F9 수정 직전 SHA `6c6c7dc097effd145347d5142cb2247015924df373f69dbf64ffe70d189e7199`의 증거를 재사용했다. 최종판과 차이는 F9 고정 문자열4바이트뿐임을 자동 검증했으며, 해당 부분은 최종 실전 화면에서 추가 검증했다. 실행 코드/글꼴/저장 코드/아이템·전투 표는 동일하다.
- 두 IPS 재적용 결과와 배포 ROM 일치. 빌드 변경 목록 재생과 원본 해시 검증 완료.

## 다음 작업과 제약

공용 아이템 이름은219/219다. 별도 상점 선택문·일반/교섭 대사·자동이동/시스템 안내·엔딩·악마 성향 표·일부 약어 및 로고는 아직 부분 미번역/미검수다. 전체 한글화 완료판은 아니며 임의의 전체 퍼센트를 제시하지 않는다. 다음에는 combat표의 미교정 시스템문구/자동이동256..280을 먼저 원문대조하고 일반교섭 블록을 정리한다.

네 번째 글꼴 페이지는 C4 00..09=gid768..777이며 실제위치는 bank31 DB40부터다. D900에는 부팅 코드가 있으므로 덮지 않는다. DB40..DBFF는24글자, 현재10개사용하여14개여유. 이름표 파서와 일반대사 파서는C4를지원하지만 c09 전체화면 오버레이 parser는여전히B8/B9/C3만 지원한다. C4를그 오버레이에넣으려면별도지원이필요하다. 동시동적글꼴31종제약은유지한다. 전투 메시지변수F9는generic악마, F4는지정악마이름이므로혼동하지말것.

옛 강제 세이브에 이미 그려진 제목·글자는 그 화면을 나갔다 돌아와야 갱신된다. 구판 세이브를 불러온 뒤 c13에서 게임 안 저장을 다시 한다. 원본 ROM/사용자 강제 세이브/기존 배터리 파일은 덮어쓰지 않았다.
