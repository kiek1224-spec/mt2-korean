# c29 레오나르드 사바토마 소환 소실 = 대사 스크립트가 `C4 FF`에서 잘림 (2026-10-01, Claude)

- 롬: `작업한 롬파일/mt2_c29_script_flow.nes` (SHA256 `bcecc3a7…cb564`, 게이트 `tools/release_c29.py`, `결과/c29/c29_release.json`, c28 대비 100바이트)
- 패치: `패치파일/mt2_c29_script_flow.ips`(일본어 원본용), `패치파일/mt2_c29_FROM_c28.ips`(133바이트)
- 빌드 `tools/build_c29.py` (c28 위, 대사 뱅크만, 코드·CHR 무변경) · 검증 `tools/verify_c29.py` · 회귀 `임시/regress_c29.sh`
- 새 도구 `tools/script_skeleton.py`: 6개 대사 블록 전 엔트리의 **명령 뼈대**를 원판과 대조(번역문은 자유, 명령 흐름은 같아야 함)

## 증상 (사용자 보고)

우에노 디바교 사바트에서 레오나르드가 사바토마를 외치면 졸개가 나와야 하는데 그냥 사라지고 전투가 끝난다.
사바토마 전에 쓰러뜨리면 피할 수 있었다. 사용자 세이브 `mt2_c28_glyph_lru_1/_3`(한글판), 원판 `Digital Devil Story - Megami Tensei 2 (J)_10`.

## 원인

- 원판 실측(같은 장면, 레오나르드 HP `$0548` 고정 + A 연타): 전투 메시지 118 「사바토마 시전」 → 전투 종료 → 대화 스크립트
  script1 352의 `EE 09`(조건 goto) → **361** `C4 FF DD 34 C9 00 C5 01 0A C5 02 0E C5 03 12 C5 04 16 FF`
  → 카운터(`$075D`) +1, 값 1..4에 따라 362/366/370/… = `FA 05 17`(사르가타나스) `FA 23 01 0B`(전투) … 로 이어 붙는 연속 전투.
  즉 「소환」은 전투 엔진이 아니라 **이벤트 스크립트가 다음 전투를 거는 것**이다. 적 그룹 `$05C0` 34→17.
- 한글판 361 = `C4 FF FF`. 카운터만 올리고 끝 → 필드로 복귀(메시지 0 → 3 COMP).
- 이유: 번역 추출에 쓴 Darrman `dialogue.tbl`(= `tools/dump_parallel.py`의 `CTRL`)에 `C4`·`C5`가 명령으로 없다.
  `C4 FF`를 「글자 C4 + 끝(FF)」으로 읽어 엔트리를 거기서 잘랐다. 나머지 `DD 34 … FF`는 고아로 0x52F60에 남아 있음(참조 없음).
  c17이 엔진 쪽 `C4` 처리는 고쳤지만 이미 잘린 엔트리는 그대로였다. 확인 가능한 가장 오래된 판 c13부터 동일.

## 전수 대조 (`tools/script_skeleton.py`)

정확한 문법(`tools/talk_grammar.py`)으로 6개 블록(전투 290·협상 251·script1 464·script2 492·script3 204·블록6 50)을
END 또는 무조건 goto(`EB`)까지 토큰화하고 텍스트·표시 코드를 뺀 명령열을 비교. 한글판 조건: B8/B9/C3 글자,
C4 01..17·20..25 글자/자동 조사(그 밖은 카운터), CD/CF/D8/D9/DB 사전(협상 블록 제외), 포인터 상위 ≥ `$C0`은 −`$2000`(bank7 `$C1A7`).

| 블록 | 엔트리 | 내용 | c28 |
|---|---|---|---|
| script1 361 | 디바교 사바트 | `C4 FF` 뒤 분기 7개 소실 | `C4 FF FF` |
| script2 485·486 | **호수**(동료 운디네가 잠수) | `C5 02 04 / C4 FF / EB 03` 의 `EB 03` 소실 | `… C4 FF FF` |

나머지는 전부 일치. script2 178–193(상점형 선택지)도 처음엔 걸렸지만 `EB 03`(무조건 goto) **뒤에** 낀 FF라 무해
(bank7 `$C34B` EB = goto, `$C35D` EC = 호출, `$C366`/`$C371` EE/ED = `$0759` 조건 goto).

호수는 「올라오지 않는다 / 포기하고 가시겠습니까?」에 아니요를 고르면 「조금 더 기다렸다…」 → 원판은 다시 질문,
세 번째에 487 「운디네가 돌아왔다 … 시오미츠타마를 가져왔다」. 한글판은 한 번 기다리면 대화 종료,
입구 483이 `C4 00`으로 카운터를 되돌리니 **시오미츠타마를 받을 수 없었다**(c17 문서의 「진행 불능 가능성」이 이것).

## 수정

- script1 361은 블록의 마지막 엔트리 → 뒤의 일본어 찌꺼기 자리로 제자리 확장(19바이트, 포인터 그대로). PRG `0x53D56`.
- script2 485(486을 안에 포함, 79바이트)를 블록 끝 빈자리 `0x5BE4E`로 복사하며 마지막 `FF` → `EB 03 FF`.
  포인터 485 `$AEB6→$BE4E`, 486 `$AECF→$BE67`. 옛 바이트는 참조 없이 남김.
- 엔진 코드는 안 건드림. `C4 FF`는 c17 W0 경로가 카운터 명령으로 처리, `C5`는 원판 핸들러 그대로.

## 검증 (`tools/verify_c29.py` → `결과/c29/c29_verification.json`)

- 뼈대 대조: 6개 블록 불일치 0 (c28은 3).
- 레오나르드(`mt2_c28_glyph_lru_3`, HP 고정, A 연타): 118 뒤 메시지 0 → **72 「사르가타나스 1마리 출현!」**, `$05C0`=$17.
  c28은 0 → 3 → 61(필드 COMP). 화면 `임시/c29/c29_msg1/pick.png`.
- 호수: 같은 세이브에서 디바교 「예」 분기(`$C16C`, sub 3) 순간 기준을 script2 483으로 바꿔 실제 엔진이 486을 돌게 함.
  아니요 ×4 → `EB` 2회, 카운터 0→1→2 → 487 도달, 화면에 「운디네가 돌아왔다 / 시오미츠타마를 가져왔다」.

## 메모

- 359 = `FA 06 01 1A`(레오나르드 전투) `EE 09`(사바토마로 끝났으면 361) 다음이 360 「신자들도 도망쳤다 / **목성의 기둥**(203)」.
  사바토마 전에 쓰러뜨리면 `EE`가 안 걸려 바로 360으로 가니 문제가 안 보였다(사용자 우회법이 맞았음).
  원판은 361 → 연속 전투 → 365 `EB 07`로 359에 돌아와 다시 레오나르드전.
- c28에서 사바토마로 끊긴 경우 목성의 기둥 없이 필드로 나왔다. 사바트를 다시 열 수 있는지는 미확인.
