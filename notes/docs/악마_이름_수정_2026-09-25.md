# c06 악마 이름과 종족명

사용자가 지정한 우선순위는 전투 중 악마 이름·종족이었다. c04를 바탕으로 고정 악마 이름 252개 항목 가운데 249개를 한글화하고 Y.H.V.H, GDR1000, LB-501A는 보존했다. 종족명은 빈 항목 0을 제외한 26개를 한글화했다. 중복 이름을 포함한 테이블 항목 수이며, 전체 게임 번역률이 아니다.

## 원인과 수정

- 악마 테이블 0x4D763의 ID 21은 여주인공 사용자 이름 RAM 포인터다. ID 253~255와 함께 원본을 보존했다. 고정 문자열 영역은 0x4D963..0x4E010이며 1709바이트 중 1565바이트를 사용한다.
- 종족 테이블은 0x6BB04, 문자열 영역은 0x6BB3A..0x6BBC3이다. 137바이트 중 98바이트를 사용한다.
- 일본어 이름 바이트가 한글 글꼴로 그대로 표시되어 엉뚱한 이름이 나왔다. 기존 공통 이름 복사 루틴 C082는 한 바이트만 복사하므로 대사의 확장 글꼴 코드를 그대로 넣어도 해결되지 않았다.
- C082를 고정 뱅크 F67E의 보조 루틴으로 연결했다. B8/B9/C3와 다음 인수를 해석해 기존 F71A 글꼴 할당기를 호출한다. X/Y를 보존하고 출력 한 칸에 해당하는 글꼴 코드 하나를 반환한다. 인수 소비는 소스 포인터 AB/AC를 증가시켜 처리한다.
- 0x40..0x97은 고정 글꼴 88개다. 0x98..0xB7은 동적 32칸이므로 고정 한글 코드로 취급하면 안 된다. 이전 인계의 고정 글자 120개 가정은 정정한다.
- 기존 글꼴 757개에 없는 룡·룩·룽·벙·샐만 빈 gid 757~761에 추가했다. 남은 빈 라이브러리 슬롯은 6개다. 빌드용 비트맵은 translations/c06_extra_glyphs.json에 고정했으므로 빌드 시 외부 글꼴 프로젝트를 요구하지 않는다.
- NMI, 부팅, 업로더는 변경하지 않았다. c04 대비 실제 변경은 2342바이트이며 이름 테이블·문자열·후크·보조 루틴·추가 글꼴 범위로 제한된다.

상점 인계에서 B8 실험 후 검은 화면이 나왔다는 관찰은 보존하되 충돌 확정으로 해석하지 않는다. 이번에 확인한 것은 이름 복사기의 확장 코드 미해석이다. 짧은 대기 시간의 검은 화면만으로 정지를 판정하지 않는다.

## 원문과 번역 자료

일본어 원본과 로컬 Darrman 자료를 대조했다. Darrman 기준 커밋은 `3da3c784fbc219343b4716298709618d326548a6`이다. 번역은 `translations/demons_ko.tsv`, `translations/races_ko.tsv`에 있으며 원문·포인터 대응은 `translations/c06_name_source.json`에 남겼다. 공식 한국어 명칭이 전부 검증된 표라고 주장하지 않으며, 이후 용어 검수 시 TSV와 실행 검증을 함께 갱신한다.

## 실행 검증과 범위

Mesen 실제 CPU에서 공통 이름 복사 경로를 실행했다. 악마 252개, 종족 26개에서 예상 글꼴 토큰과 실제 출력이 모두 일치했고 큐 포화는 0건이었다. 종족 검사에서는 진단용으로 이름 테이블 서술자를 종족 테이블로 바꿨다. 종족 21은 원래 이름 21의 특수 분기를 피하려고 진단용 ID 0으로 호출했다. 모든 종족이 일반 전투 화면에 등장하는 장면을 각각 시각 검수한 것은 아니다.

실제 전투는 진단용 상점 이벤트에서 게임의 FA05/FA06 명령을 호출했다. 전투 진입용 이벤트 변경은 배포 롬에 없다. `tools/verify_c06.py`가 배포 후보에서 진단용 변경을 정확히 재구성하고 보관된 실행 기록의 ROM 해시와 대조한다.

- `결과/codex/verification/c04_battle_8d/screen4.png`: c04 픽시 이름 깨짐 대조군.
- `결과/codex/verification/c06_battle_8d/screen4.png`: 픽시 등장.
- `결과/codex/verification/c06_battle_7f/screen4.png`: 그린 슬라임 등장.
- `결과/codex/verification/c06_battle_a6/screen4.png`: 백룡 등장, 추가 글리프 룡 확인.
- `결과/codex/verification/c06_pixie_commands/sheet.png`: 명령 선택, 대상 지정, 공격에서 이름 유지.
- `결과/codex/verification/c06_coldboot/screen3.png`: 세이브 없이 시작하여 도입부 진행.
- `결과/codex/c06_demons_runtime.json`, `c06_races_runtime.json`: 전체 이름 처리 검사.
- `결과/codex/c06_verification.json`: 수정 범위, 실행본 해시, 사용자 세이브 보존, IPS 두 종류 왕복 검증.

동적 글꼴 풀은 기존 32칸 구조를 유지한다. COMP 다수 악마 목록, 긴 상점 목록, 모든 전투 조합, 장시간 플레이 전체를 검증한 것은 아니다. 교섭 대화·상점 이름·상점 소지금 제목·다른 전투 UI의 기존 미번역은 남아 있다. 부팅 속도 개선도 이번 범위에 없다.

## 재현과 배포

```
python tools/build_c06_names.py
python tools/verify_c06.py --release
```

첫 명령은 실험 경로에 후보를 생성한다. 두 번째는 보관된 실행 검증과 바이트가 일치하고 정적 검증에 성공할 때만 배포 파일을 쓴다. 번역이나 코드가 바뀌면 해당 실행 검증을 새로 만들어야 한다.

- 롬: `작업한 롬파일/mt2_codex_c06_demon_names.nes`
- 일본어 원본용: `패치파일/mt2_codex_c06_demon_names.ips`
- c04 갱신용: `패치파일/mt2_codex_c06_FROM_c04.ips`
- 롬 SHA256: `11d7ee041aec1d2ef32ae2be740dea5b9f491515ff2ccb5e46865a793a63e4e8`

세이브에 이미 그려진 이름은 남아 있을 수 있으므로 새 전투를 시작하거나 창을 닫았다가 열어 판정한다. 원본 사용자 세이브는 수정하지 않았다.
