## 확정된 수정과 검증

c07은 제공된 상점의 아이템 8개를 목록과 실제 아이템 테이블 양쪽에 반영했다. 잭나이프·청동검·시미터·브로드소드·전투복·하이레그 아머·케블라조끼·철투구다. 목록의 여성 기호가 바자로 보이던 부분도 남/여로 표시했다. 소지금, 네/아니요, 구매 확인, 판매 견적과 판매 후 질문을 수정했다. 구매 184→84, 취소 184 유지, 이름 286개 CPU 검사, 목록 8개 실제 비트맵 대조, 반복 거래 화면에서 금 글꼴 보존과 화면 표시 중 업로드 0건, 초기 부팅·픽시 전투·IPS 두 종류를 확인했다. 세이브 원본은 보존했다.

c07의 글꼴 할당 규칙은 c06과 다르다. B7을 금(gid 112) 전용으로 고정하고 일반 순환 슬롯은 98..B6의 31칸이다. 파서와 업로더의 카운터 양쪽에서 금을 제외한다. 금을 요청할 때마다 업로드하여 기존 세이브의 CHR 내용도 갱신한다. 빈 큐 NMI 분기와 부팅은 바꾸지 않았다. 새 글자 철은 gid 762이며 빈 라이브러리 슬롯은 5개다. 상점 목록은 아이템 이름 테이블을 읽지 않고 별도 선택지 문자열(type 6)을 사용한다는 점이 중요하다.

c06은 악마 고정 이름 252개 항목 중 249개를 한글로 바꾸고 알파벳 3개를 보존했다. 종족명은 빈 항목을 제외한 26개를 번역했다. 사용자 지정 이름 포인터 4개는 보존했다. 실제 CPU 이름 처리 루틴으로 252개와 26개를 전부 검사했고 불일치·큐 포화는 0건이었다. 픽시·그린 슬라임·백룡의 전투 등장 화면, 픽시 명령 선택 및 공격, 초기 부팅을 확인했다. 진단용 이벤트 변경은 배포본에서 제외했다. 검증 스크립트가 진단용 변경만 재구성해 실행 기록의 ROM 해시와 대조하므로 검증한 바이트와 배포본의 연결을 확인할 수 있다.

이름 복사 루틴은 원래 확장 한글 코드를 해석하지 않았다. c06은 공통 이름 복사에 B8/B9/C3 처리를 넣고 기존 업로더를 호출한다. 0x98..0xB7은 고정 글자가 아니라 동적 슬롯이다. 고정 글자 88개와 기존 확장 글꼴을 재사용하고 룡·룩·룽·벙·샐 5글자만 빈 슬롯에 추가했다. 이전 인계의 확장 코드 사용 시 검은 화면이라는 기록은 충돌 확정 근거가 아니며, 이번에 확인한 핵심 원인은 확장 코드를 타일 값으로 그대로 복사하는 경로다.

c02는 글꼴 업로드 큐가 비어도 NMI에서 불필요한 작업을 했다. 원래 DMA 경로와 비교하고 지연만 넣은 대조군을 통해 처리 시간에 따른 화면 깨짐을 재현했다. c03은 빈 큐일 때 원래 DMA로 바로 가며, 글꼴이 필요하면 기존 업로더를 유지한다. 빈 큐 추가 비용은 89에서 14 CPU 사이클로 줄었다.

제공된 c02 세이브로 Mesen에서 아래·위 이동 67프레임을 비교했다. COMP를 열어 새 한글 문구를 확인하고 닫은 다음 다시 67프레임을 비교했다. 총 134개 화면이 원래 DMA 대조군과 픽셀 단위로 일치했다. 글꼴 큐 소진, 사용자 세이브 원본 해시 보존, 일본어 원본용·c02용 IPS 왕복도 통과했다. c02 대비 변경은 58바이트이며 NMI 후크·분기와 COMP 문자열 영역에만 있다.

새 번역 32개 중 c03에서 메시지 ID 3을 명시적으로 삽입했다. `컴퓨터 가동 / 소환 / 귀환 / 해제 / 순서 변경 / 메시지 속도`이며 기존 53바이트 공간에 51바이트로 들어간다. LINE 6개와 END를 보존했다. `translations/v37_encoding_recovery.json`에 기존 글꼴 코드와 비트맵을 고정했다. 이후 확인하니 초안 4개는 현재 ROM 문구와 이미 동일하고, 23개는 현재 할당 칸보다 길며, 1개는 `뺄` 글리프가 필요하다. `결과/codex/combat_draft_fit.json`을 참조한다.

c04는 명령창 제목 다섯 바이트만 고쳤다. 기존 글꼴 페이지 6의 `명`·`령` 타일을 사용한다. 제공된 c02 세이브로 Mesen 메뉴를 열어 c03 대비 화면 차이가 제목 영역에만 있는 것을 확인했고 두 IPS 왕복도 통과했다. c05 아이템 안내 문구는 `결과/codex/experiments/`의 실험판으로만 보존했다. 제공된 세이브에 아이템이 없어 해당 창의 실행 화면은 확인하지 못했다.

부팅은 이번에 수정하지 않았다. v37 계열은 처음에 256 KiB CHR-RAM을 초기화한다. 원래 v37도 기다리면 부팅하므로 이전 c02를 검증된 부팅 개선판으로 설명하지 않는다. 전체 플레이와 항상 바쁜 글꼴 큐의 모든 NMI 경로까지 검증된 것은 아니다.

## 다음 첫 작업

**c07을 기준으로 다른 상점의 목록용 선택지와 실제 아이템 이름을 대조해 다음 묶음을 정한다.** 한 쪽만 번역하면 목록이나 구매 확인에 미번역이 남는다. 아이템 테이블 219개 중 이번에 바꾼 8개 이외의 데이터는 보존했다. 첫 상점 검증을 그대로 반복하지 말고 새 대상에 필요한 문자·공간부터 계산한다. 아이템 문자열 영역은 1467/1467바이트로 가득 찼고 선택지 영역은 679/804바이트를 사용한다. 빈 글꼴 5개 제약도 고려한다.
필드·전투의 별도 소지금 제목(현재 깨진 글자), 교섭 대화와 COMP 여러 악마 목록은 남아 있다. 전투 문구의 기존 긴 초안 23개도 공간 처리가 필요하다. 전체 번역률은 아직 신뢰할 만하게 확정하지 않았다.

사용자 세이브는 프로젝트 옆 `Mesen_2.2.1_Windows/SaveStates/`에 있다. c04 `_2.mss`는 상태·장비, `_3.mss`는 상점 목록이다. `_3.mss`를 불러온 뒤 B→300프레임 대기→B→300프레임 대기로 나와, 아래 8프레임→120프레임 대기→위 8프레임→300프레임 대기해야 재입장한다. 위로만 누르면 벽에 막힌다. A 8프레임→240프레임 대기로 새 목록을 확인한다. 정확한 입력은 c07_shop_final/run.json에 있다. 오래된 세이브의 목록·제목은 캐시돼 있으므로 새 롬 실패로 오판하지 않는다. 추가 세이브 요청은 현재 필요하지 않다.

## 사용량과 작업 원칙

사용자는 현재 모델을 Astra high라고 알렸다. 도구가 모델·effort를 독립적으로 확인해 준 것은 아니다. 2026-09-25 c07 중단 후 재개 시 조회한 Plus 계정 잔여량은 5시간 100%, 주간 36%였다. 계정 전체의 시점별 수치이므로 다음 회차에 필요하면 다시 조회한다. 초기화 크레딧은 사용하지 않았다.

완료된 조사·동일 검증을 반복하지 않고 한 문제와 한 화면씩 진행한다. 새 하위 에이전트는 추가하지 않았다. 원본 세이브·기준 롬을 보존하고 수정본의 입력, 화면, 해시, 패치와 재현 명령을 남긴다. 5시간 재개 알림은 이미 목적이 끝났으며 새로 예약하지 않는다.
