- 패치: `패치파일/mt2_c27_menu_nmi.ips`(일본어 원본용), `패치파일/mt2_c27_FROM_c26.ips`

- 도구: `임시/c27_nmi_time.py`(NMI마다 마지막 `$2007` 시각·기록 크기·업로드 여부), `임시/c27_shot.py`(세이브→입력→화면·CHR),
  `임시/c24_render_watch.py`(렌더링 중 `$2007` 쓰기)

## 증상

사용자 보고: 「팔콘 아이 장착한 상태로 메뉴로 돌아가면 가끔 그래픽이 깨진다, 시한폭탄 같다」. 세이브 `mt2_c26_casino_5`(1인칭 메뉴)·`_1`(장비 화면).
장비 화면에서 B로 메뉴에 돌아오는 순간 **배경 전체에 초록 점**이 깔린다. 팔콘 아이 전용이 아니라 장비 화면을 닫을 때 공통(발터 PPK로도 재현).

## 원인 (측정)

1. 바뀐 CHR 바이트가 전부 **값 = 주소 아래 바이트**(`0x1802←02`, `0x1803←03`, 뱅크 111·113·255 몇 바이트) → c24와 같은 「렌더링 중 `$2007`」.
   뱅크 6 타일 0이 배경 빈 타일이라 화면 전체에 점이 찍힌다.
2. 쓰는 곳 `$FA8A`(원판 `$FA64` 세로 기록기). 장비 화면을 닫으면 명령창을 `$0380=$C6` = **세로 70바이트**(10줄×7열)로 다시 그린다.
   버퍼 `$0384~$03C9`가 딱 70바이트라 원판이 만드는 **가장 큰 기록**이다. 원판은 `$FA31`에 ~620사이클에 도착해 259행 근처에서 끝난다.
3. c24가 업로드를 옮긴 텍스트·레코드 경로 `$F8FE → $FFF4 → $FF8D(bank31 $C000: W2 → $DC00 글자 1개) → $FA31`에서,
   글자 큐(`$6022≠$6023`)가 비어 있지 않으면 업로드가 ~420사이클을 먼저 쓴다 → 70바이트 기록이 **사전 렌더 줄·0행**까지 밀림
   (c26: NMI 시작부터 2,479사이클, 0행 dot 303에 끝).
4. 「가끔」인 이유: 그 NMI에 글자가 아직 큐에 남아 있을 때만 터진다. 장비 화면이 메뉴 글자를 캐시에서 밀어내서
   (팔콘 아이 등 긴 이름) 돌아올 때 다시 올릴 글자가 쌓여 있으면 확률이 높다. `_1`은 그 상태로 저장돼 있어 B만 누르면 매번 터진다.
   c24 때 측정한 「업로드 프레임 최악 255행」은 필드·작은 기록 기준이었고, 세로 70바이트 창 기록과의 겹침은 빠져 있었다.

## 수정

bank31 `$C000`(원래 `JMP $DD75` W2)을 `JMP $DFAE` 검사로:

```
DFAE  LDA $0380 / BEQ go        ; 기록 없음($F904 경로) → 그대로
      BMI skip                  ; 세로 창 기록 → 이번 NMI는 글자 업로드 안 함
      walk: Y += 3 + count …    ; 가로 기록은 버퍼 사용량 U를 셈
      U > 48 → skip
go    JMP $DD75                 ; W2 → $DC00 (기존)
skip  RTS                       ; 글자는 다음 NMI에
```

- 한 글자씩 찍는 작은 텍스트 기록(U ≤ 48)은 지금처럼 **같은 NMI**에 업로드 → 새 글자가 옛 타일로 한 프레임 보이는 일 없음.
- 큰 창 기록 프레임만 업로드가 한 프레임 밀린다. 창을 새로 그릴 때 글자는 원래도 NMI당 1개씩 올라가므로 체감 차이 없음.
- W2 이름표는 원래 `$0380` 작업이 있으면 건너뛰므로 영향 없음. 화면 꺼진 상태 직접 비우기(`$F72C JSR $DC00`)는 이 입구를 거치지 않는다.
  `$F744 JSR $C000`은 bank30이라 무관.
- 여유: 업로드 + 가로 U=48 ≈ 15×48 = 720사이클 → 업로드 프레임 끝이 약 257행 이내(측정 최악은 아래).

## 참고

- 이미 점이 찍힌 세이브스테이트는 CHR째 저장돼 있으니 전원 → 인게임 LOAD. `_1`·`_5`는 아직 손상 전이라 c27에서 그대로 불러도 된다.
- NMI 안에서 `$2007`을 쓰는 원판 경로(`$FA31`/`$FA64`/`$FAA8`/`$FC22`/`$F9F3`/필드 `$FAF2`) 중 업로드와 겹칠 수 있는 건
  `$FA31`(여기서 막음)과 `$F904` 뒤의 `$FC22`(≤9바이트)·`$F9F3`(팔레트 32바이트)뿐이고 뒤 둘은 작다.
