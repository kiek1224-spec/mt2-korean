# 2026-09-21 인수 기록

## 현황과 판단

이 프로젝트는 Git 저장소가 아니며 기존 파일은 수정하지 않았다.
옛 경로 `Desktop/새 폴더 (3)/Mesen_2.2.1_Windows`는 없고 실제 에뮬레이터는 형제 폴더에 있었다.
폰트는 형제 MT1 프로젝트의 `galmuri/galmuriM_8x8.ttf`를 읽어 타일로 추출했다.
다른 게임 프로젝트의 파일은 수정하지 않았다.

인수 당시 실험 롬 42개를 확인했다. 정확한 목록과 해시는 `결과/codex/rom_inventory.json`을 따른다.
v09 / v10(기본판) / v11은 동일한 파일이다. v19, v32, v37, v40은 내용이 다른 실험이다.
v37은 CHR-ROM 없이 512 KiB PRG와 NES 2.0 CHR-RAM 선언을 사용한다.
부팅/타이틀까지 진행했으나 독립적인 게임 내 검증을 마치지는 않았다.

원본 전투 스테이트를 v32/v40에 불러온 비교에서는 화면이 깨졌다.
이는 **다른 메모리 배치의 롬에 원본 스테이트를 얹은 실험**이므로 해당 버전이 항상 깨진다는 근거가 아니다.
`결과/codex/battle_comparison.png`는 이 한계를 가진 탐색 자료다.
반면 v09가 CHR 뱅크 3의 원래 일본어 글꼴을 한글로 덮는 것은 파일 비교로 직접 확인했다.

## 완료한 변경

- 새 `mt2probe.py`: Mesen 경로 탐색, 고유 ASCII 임시 폴더, 체크포인트 캡처,
  입력 폴링 콜백, 실행 성공·스테이트 로드 검사, 로그·원본 해시 기록.
- `tools/recover_legacy.py`: 기존 롬 변경 구간과 변경된 이름 140개 추출.
- `build.py`: 원본 해시 검사, 검토 가능한 번역 데이터로 c01 빌드, IPS 생성, v09 정확 복원.
- `verify.py`: 코드·텍스트·글꼴 변경 범위 검사, IPS 왕복 검증, Mesen 화면 회귀 검사.
- 번역 데이터와 메뉴 타일을 `translations/`에 보존해 다른 프로젝트 파일 없이 빌드할 수 있게 했다.

기존 참고 자료의 `emu.exit()`는 현재 Mesen에서 종료하지 않았다.
공식 Lua 문서의 `emu.stop(0)`로 고쳤고, 스테이트 생성은 `exec` 메모리 콜백에서 수행하도록 했다.
처음의 시간 초과 테스트는 완료 검증으로 세지 않았고 수정 후 정상 종료된 실행만 사용했다.

초기 탐색 중 Mesen이 공용 이름 `input.sav`에 시험용 배터리 RAM을 기록한 것을 확인했다.
러너를 실행마다 고유한 ROM 이름을 쓰도록 바꿔 기존 게임 세이브와 분리했다.
최종 검증은 이 수정 후 다시 수행했고 모두 통과했다. 초기 `input.sav`는 삭제하지 않았다.

공식 근거:

- [Mesen Lua API](https://github.com/SourMesen/Mesen2/blob/master/UI/Debugger/Documentation/LuaDocumentation.json)
- [N163 / Mapper 019](https://www.nesdev.org/wiki/INES_Mapper_019)

## 검증과 남은 범위

확정 결과는 `결과/codex/verification.json`에 기록한다.
원본·c01 각각 부팅, 다시 그린 필드 메뉴, 상태 화면, 지도 이동을 검사한다.
확정 필드 스테이트는 `결과/codex/verification/c01_field/final.mss`이며 c01 전용이다.

c01의 전투 명령·악마 명령·게임 오버·무기 선택은 표에 번역이 들어 있으나,
각 화면의 완전한 실제 표시 검증까지 끝난 것은 아니다.
게임 실행 코드 변경은 없고, 대사와 이름은 원본 상태로 유지했다.
마법명 등을 다시 넣기 전에는 별도 한글 출력 방식이 필요하다.

## 다음 시작점

`README.md`의 빌드 명령으로 현재 결과를 재현하고 검증 결과를 읽는다.
다음 단계의 핵심은 기존 동적 출력 실험을 같은 롬의 새 스테이트로 검증하는 것이다.
원본 스테이트를 CHR-RAM 판에 바로 얹어 나온 화면만으로 결론 내리지 않는다.
복구 번역은 `translations/legacy_v09_text.json`에서 원시 바이트와 함께 확인할 수 있다.

사용량 절약을 위한 이번 회차 마감 지점과 바로 할 일은 프로젝트 루트의 `RESUME.md`에 기록했다.
